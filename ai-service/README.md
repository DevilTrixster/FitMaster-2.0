# FitMaster AI Service

AI service генерирует адаптивный шаблон, но не владеет базой данных и ничего не сохраняет в отдельную БД. Единственный источник данных — PostgreSQL основной части FitMaster, к которому обращается TypeScript-приложение.

## Что происходит после тренировки

1. Страница сохраняет фактические показатели в `user_workout_result.actual_data`.
2. TypeScript-сервер переводит тренировку в `COMPLETED` и запускает адаптацию в фоне.
3. TypeScript собирает профиль, текущую тренировку, историю последних завершённых тренировок, замены и доступные упражнения из основной БД.
4. AI Service рассчитывает индикаторы, отправляет компактный контекст в OpenRouter и проверяет полученный JSON.
5. TypeScript проверяет шаблон по своим правилам и сохраняет его через `CreateWorkoutPatternUseCase` в `workout_pattern`, затем создаёт следующую запись в `user_workout`.

**В AI Service нет подключения к PostgreSQL.** Он не создаёт `user_biography`, `workout_history` или `adaptation_generation` и не требует отдельной базы `ai-fitmaster`. Профиль, история и созданный шаблон принадлежат основной базе данных.

## Настройки `.env`

В корневом `.env` оставь подключение основной базы и параметры AI. Пример:

```env
DATABASE_URL=postgresql://user:password@localhost:5432/fitmaster_db
AI_SERVICE_URL=http://127.0.0.1:8000
AI_SERVICE_TIMEOUT_MS=150000
AI_GENERATION_TIMEOUT_SECONDS=100
AI_API_KEY=your-openrouter-api-key
AI_BASE_URL=https://openrouter.ai/api/v1
AI_MODEL=openrouter/free
```

`API_KEY` поддерживается как альтернативное имя для `AI_API_KEY`. Используется только `openrouter/free`: OpenRouter динамически выбирает доступную бесплатную модель. Не указывай платную модель; заданное в `.env` имя конкретной модели будет проигнорировано, чтобы приложение не было привязано к модели, которая завтра может исчезнуть из бесплатного списка.

Установленные значения тайм-аутов рассчитаны так, чтобы AI мог сделать две попытки. Старый `AI_SERVICE_TIMEOUT_MS=60000` автоматически повышается минимум до 120 секунд. В Python значение `AI_GENERATION_TIMEOUT_SECONDS` ограничено диапазоном 75–110 секунд. Эти параметры влияют на ожидание, но не отменяют ограничения доступности и квоты бесплатных моделей OpenRouter.

## Запуск в Windows

Из корневой папки проекта:

```powershell
py -3 -m venv .\ai-service\.venv
.\ai-service\.venv\Scripts\python.exe -m pip install -r .\ai-service\requirements.txt
Set-Location .\ai-service
.\.venv\Scripts\python.exe -m uvicorn main:app --host 127.0.0.1 --port 8000
```

В другом терминале запусти основное приложение командой `npm run dev`. Можно запускать оба процесса из корня командой `npm run dev:all`. При изменении `requirements.txt` этот скрипт пересоздаст виртуальное окружение AI-сервиса.

Документация API: `http://127.0.0.1:8000/docs`. Обычная проверка сервиса: `http://127.0.0.1:8000/health` — она **не отправляет запрос к модели** и не расходует бесплатную квоту. Проверка реального ответа модели: `http://127.0.0.1:8000/health/ai` — этот endpoint делает отдельный бесплатный тестовый запрос.

## Проверка

1. Убедись, что в `.env` указан правильный `DATABASE_URL` основной базы и есть действующий `AI_API_KEY`.
2. Запусти основной сервер и AI Service.
3. Открой активную тренировку, выбери оценки самочувствия и усталости от 1 до 5, заполни значения подходов и заверши тренировку.
4. Проверь, что `user_workout_result.actual_data` сохранены, а `user_workout.status` стал `COMPLETED`.
5. Дождись фоновой адаптации и проверь в `workout_pattern` строку с типом `ADAPTIVE` и источником `ADAPTATION`. Следующая тренировка должна ссылаться на её UUID в `user_workout.pattern_id`.
6. При ошибке проверь журнал Node-сервера и отдельно открой `/health/ai`, если нужно проверить доступность OpenRouter.

Если раньше была создана база `ai-fitmaster`, этот код больше к ней не обращается. Она не удаляется автоматически: при желании удали её вручную в pgAdmin после проверки, что старые записи больше не нужны.
